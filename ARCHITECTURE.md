# Архитектура проекта

## Технологии

- V0.0: TypeScript, React, Vite, Vitest.
- V0.1: Three.js / React Three Fiber для 3D-сцены.
- V0.3: исследовать Arduino CLI для компиляции и avr8js для исполнения прошивок UNO.
- V0.4: исследовать Rapier для физики тел, приводов и суставов.
- V0.6: локальный помощник для USB-загрузки, когда это необходимо и разрешено.

**Внимание:** 3D, AVR, Rapier и Arduino CLI сейчас только запланированы и не подключены.

## Логические слои

```text
React UI: Сборка / Схема / Код / Испытания
           |
     Project Domain
       /    |     \
Electrical |   Mechanics
           |
       MCU Runtime
           |
  State & Diagnostics
```

Слои не должны содержать логику, жёстко относящуюся только к 2WD-машинке или только к манипулятору.

## Доменная модель (целевое направление)

- `Project`: ID, schemaVersion, boardConfig, компоненты, соединения, исходники, среда.
- `ComponentDefinition`: параметры, контакты, коллайдеры, монтажные точки и физическая модель.
- `ComponentInstance`: идентификатор типа, параметры, положение, ориентация.
- `MechanicalJoint`: тип, якоря, оси, ограничения и привод.
- `ElectricalNet`: соединённые пины и тип сигнала/питания.
- `FirmwareBuild`: исходники, выбранная плата, зависимости и артефакт компиляции.
- `SimulationSession`: время моделирования, начальное состояние и диагностика.

## Цикл симуляции

1. MCU выдаёт сигналы на GPIO и периферию.
2. Электрическая модель обновляет состояние драйверов.
3. Драйверы изменяют силы или скорости механических приводов.
4. Физика выполняет фиксированный шаг.
5. Датчики измеряют сцену и подают данные на MCU.
6. UI визуализирует состояние, а диагностика сохраняет события.

Точность временной синхронизации тактов AVR, прерываний и физики — отдельная техническая задача. Нельзя выдавать декоративное движение за исполнение скетча.

## Системы единиц

В ядре: метры, килограммы, секунды, радианы. В интерфейсе можно показывать миллиметры и градусы.
