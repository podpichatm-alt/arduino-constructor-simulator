# V0.1.1 — механические соединения

Работающая кинематика сборок, без моделирования сил, инерции, столкновений и MCU.

## Управление, включая Android

1. Откройте **Каталог / сборка**, добавьте детали. Габариты свободной детали можно изменить до соединения.
2. Нажмите **Соединить**. Выберите ведущую деталь и её точку, затем ведомую деталь и совместимую точку. Можно использовать выпадающие списки или нажимать модели и подсвеченные точки в сцене. На телефоне списки не требуют попадания пальцем в маленькую 3D-точку.
3. Выберите **Fixed Joint**, **Revolute Joint** или **Axle Joint**. Нажмите **Совместить и соединить**. Первая сборка остаётся на месте; вторая совмещается крепёжными рамками вместе со своими дочерними деталями.
4. Выберите закреплённую деталь и откройте **Свойства**. Свободное перемещение и вращение заблокированы. Для подвижного соединения есть отдельный ползунок с текущим углом в градусах, пределы и **Сбросить угол** (сброс в 0°, ограниченный допустимым диапазоном).
5. Соединения доступны также в списке **Соединения** каталога. Выбор открывает свойства ведомой детали. Здесь можно изменить имя, тип, ведущую деталь, локальные точки, ориентации и оси обеих рамок. Изменение рамок немедленно пересчитывает совмещение; изменение ведущей детали сохраняет мировую позу.
6. **Отсоединить деталь** удаляет входящее соединение, сохраняя мировое положение и ориентацию всей ведомой ветки. После этого доступны свободные трансформации и назначение другой свободной группы-родителя.

Классы креплений: `surface` и `axle`. Соединяются точки одного класса; Axle требует двух осевых точек. Это проверка класса, а не инженерная проверка диаметра вала, допуска или реальной механической совместимости. Точки `top`/`bottom` — универсальные проектные рамки, а не координаты реальных отверстий PCB.

Точки выделенной детали показаны жёлтым, исходная точка в режиме соединения — зелёным. Оси связей подсвечиваются при выборе ведущей/ведомой детали: Fixed — серым, Revolute — янтарным, Axle — голубым. Список сборки и инспектор показывают, какие детали закреплены. Отмена сенсорного жеста откатывает незавершённое свободное перемещение и освобождает камеру.

Камера: один палец — вращение; два — масштаб/сдвиг. Панели скрываются кнопками; ползунки, списки и кнопки работают независимо от 3D-инструмента.

## Шаблоны

**2WD:** шасси — корень; моторы, опора, UNO и L298N закреплены Fixed-связями. Колёса закреплены Axle-связями на осевых точках моторов. Перемещение и вращение шасси переносят весь робот; вращение колеса оставляет его на валу. Схема проводов не моделируется; никаких новых заявлений о пинах или работе L298N здесь нет.

**Манипулятор:** основание закреплено в мире; поворотная платформа, плечо, локоть и кисть имеют независимые Revolute-связи, остальные детали — Fixed. Чтобы переместить всю руку, выберите основание и снимите **Закрепить основание в мире**. Угол сустава двигает только его ведомую ветку. При копировании сборки копия основания становится свободной, внутренние соединения сохраняются.

Изменение габаритов детали с входящими или исходящими соединениями запрещено: сначала отсоедините её крепления. Это исключает незаметное изменение физического смысла сохранённых локальных рамок. Удаление детали удаляет её поддерево и затрагивающие его соединения. Дублирование создаёт независимую ветку с новыми ID и копиями внутренних связей; входящая связь выбранного корня не копируется.

## Модель и кинематика

Формат `schemaVersion: 2` сохраняет `components` и отдельный массив `joints`. У связи есть ID, имя, тип, ведущая и ведомая стороны, угол и пределы. Сторона содержит ID детали, необязательный ID каталожной точки и собственную локальную рамку `frame = { position, rotation, axis }`. Рамки независимы от `parentId`; этот атрибут остаётся только для свободной группировки. У детали со входящим соединением `parentId` всегда `null`.

Единицы ядра — метры и радианы; Y направлена вверх. Положение дочернего тела вычисляется заново, без накопления численной ошибки:

```text
A(frame) = T(position) · EulerXYZ(rotation) · Align(+Y, normalized(axis))
Wchild = Wparent · A(parentFrame) · Ry(angle) · Rx(π) · inverse(A(childFrame))
```

`Rx(π)` совмещает точки и противопоставляет локальные оси креплений. Вращение происходит вокруг оси Y ведущей рамки в её крепёжной точке, а не центра модели. Для Fixed угол всегда нулевой. Axle использует ту же точную вращательную кинематику, но требует осевые точки при создании; это не расчёт вращения под нагрузкой.

Для свободной группы действует обычная локальная поза. При смене родителя используется `inverse(WnewParent) · Wchild`, поэтому мировые координаты сохраняются. При смене ведущего тела соединения пересчитывается ведущая рамка с сохранением текущего угла и мировых матриц ведомого поддерева.

Валидатор запрещает циклы, отсутствующие детали/крепления, повтор ID, несколько ведущих связей на одну деталь, одновременный `parentId` и joint, закрепление в мире ведомой детали, неконечные числа, неверные оси и ограничения. Поддерживаются деревья и отдельные свободные детали, не замкнутые кинематические цепи. Лимиты: 300 деталей, 299 связей, 32 уровня, JSON 2 МБ, координаты локальных поз и рамок ±10 м, габариты 1–2000 мм, углы и ограничения ±360°.

## Совместимость с V0.1

Сохранён прежний ключ localStorage `arduino-constructor.project.v1`. При чтении `schemaVersion: 1` проект автоматически мигрирует:

- Сохраняются ID, имена, габариты, точки креплений и мировые матрицы всех деталей.
- Старые связи `parentId` превращаются в Fixed или Revolute с реальными локальными рамками. Старые углы переносятся в соединения. У свободного корня старый угол запекается в его ориентацию.
- У стандартных деталей 2WD с исходными ID/типами добавляются недостающие связи в **текущих мировых позах**. Пользовательская иерархия не заменяется, потенциально циклическая добавочная связь пропускается. Разобранный/изменённый V0.1-проект не пересобирается насильно: для исправления положения креплений используйте редактор рамок или новый шаблон.
- До первой перезаписи исходный JSON сохраняется без изменений в `arduino-constructor.project.v1.schema1-backup`. При ошибке создания backup исходное сохранение не перезаписывается. Повреждённые данные также не перезаписываются автоматически.

Резервную копию можно получить из Chrome DevTools командой `localStorage.getItem('arduino-constructor.project.v1.schema1-backup')` и сохранить в файл. Импорт обоих форматов поддержан; экспорт использует schemaVersion 2. Камера и открытые панели, как прежде, не входят в JSON.

## Геометрия и достоверность размеров

Использованы собственные составные модели: UNO с USB/питанием, корпусом DIP и рядами контактов; сервопривод с корпусом, ушками и качалкой; TT-мотор с редуктором, металлическим корпусом и осью; L298N с радиатором и клеммами; механические звенья и захват. Ряды повторяющихся контактов рисуются через instancing; шрифты/модели из сети не загружаются.

Контур UNO уточнён до 53.4 × 68.6 мм по [официальному Arduino UNO Rev3](https://docs.arduino.cc/hardware/uno-rev3/). Высота навесных деталей, их размещение, другие модули и механические детали остаются параметрической проектной геометрией с явно указанным статусом в каталоге/инспекторе. Они не выдаются за паспортную CAD-модель конкретного производителя. Габариты существующих импортированных экземпляров не меняются. Для реальной конструкции нужны измерения конкретных моторов, сервоприводов, модулей и реальных монтажных точек; размеры вариантов TT/L298N не подменяются случайными спецификациями.

## Проверки и запуск

```bash
npm ci
npm run typecheck
npm test
npx playwright install chromium
npm run test:e2e
npm run build
npm run dev -- --host 0.0.0.0
```

В Codespaces откройте **Ports → 5173 → Open in Browser**, оставляя порт приватным. Node.js 22+. В Linux без библиотек браузера используйте `npx playwright install --with-deps chromium`.

Unit-тесты проверяют расстояния между креплениями, смещённые оси, вложенные цепочки, ограничения, перенос всей сборки, блокировку колёс, reparent/detach без скачка, отсутствие дрейфа и миграцию настоящих JSON V0.1. Playwright проверяет desktop и профиль Pixel 7: прежние сценарии редактора, создание и изменение связей, отказ при цикле, сенсорный ползунок, JSON/backup и восстановление. Эмуляция Chromium не заменяет проверку реального Android GPU и поведения конкретного телефона.

## Перенос через Codespaces с Android при отказе GitHub push

Если среда не имеет права записи, готовые изменения поставляются как `arduino-constructor-simulator-v0.1.1.bundle` и патч. Скачайте bundle на телефон, затем в Codespaces Explorer используйте **Upload…**, чтобы загрузить его в каталог репозитория. В терминале:

```bash
git fetch ./arduino-constructor-simulator-v0.1.1.bundle refs/heads/feature/v0.1.1-mechanical-joints:refs/heads/feature/v0.1.1-mechanical-joints
git switch feature/v0.1.1-mechanical-joints
npm ci
npm run dev -- --host 0.0.0.0
```

Если локальная ветка с таким именем уже существует, не перезаписывайте её: сначала проверьте `git log`/`git status` и используйте другое имя назначения после двоеточия. Затем отправьте ветку из авторизованной Codespaces:

```bash
git push -u origin feature/v0.1.1-mechanical-joints
```

На GitHub откройте **Compare & pull request**, база — `main`. Force push не нужен. Bundle содержит историю Git и проверяется `git bundle verify ./arduino-constructor-simulator-v0.1.1.bundle`; `node_modules` в него не входят.
