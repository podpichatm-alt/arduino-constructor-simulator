# Roadmap — Arduino Constructor & Simulator

Сроки предварительные; этапы принимаются **по работающим демонстрациям**, а не по скриншотам.

| Версия | Результат | Критерий приёмки | Статус |
|---|---|---|---|
| V0.0 | Репозиторий, документация, React/Vite/TS, тестовый каркас | Проект запускается и собирается | Подготовлено; тестовый запуск требует установки npm-пакетов |
| V0.1 | Универсальная 3D-сцена и два шаблона | Размещение/поворот/выбор деталей и основы механических связей | План |
| V0.2 | Электрический редактор | Пины и соединения сохраняются, проверяются ошибки | План |
| V0.3 | Arduino C++ и эмулятор AVR | Скомпилированный `.ino` меняет GPIO виртуальной UNO | План |
| V0.4 | Физический движок | Движение 2WD и перемещение кубика манипулятором | План |
| V0.5 | Проекты, сохранения, библиотека компонентов | Проект сохраняется и восстанавливается, новые типы подключаются | План |
| V0.6 | Связь с реальной Arduino | Сборка, выбор USB-порта, загрузка и мониторинг | План |
| V0.7 | Свободная механика, STL и расширенные устройства | Собирается механизм вне встроенных шаблонов | План |
| V1.0 | Публичная версия | Регрессионные тесты, руководства, стабильный UX | План |

## Главные риски

1. Совместимость avr8js, Arduino CLI и библиотеки Servo с реальной прошивкой.
2. Корректная синхронизация MCU, электрических сигналов и физики.
3. Различие между красивой 3D-анимацией и предсказуемым движением механизма.
4. Лицензии и расширяемость сторонних библиотек.

## Приоритет прямо после V0.0

1. Зафиксировать `package-lock.json` после `npm install`.
2. Выполнить `npm run typecheck`, `npm test`, `npm run build`.
3. Начать V0.1 с 3D-сцены, не нарушая слои доменной модели.
4. Параллельно сделать небольшой PoC: скетч → компиляция → AVR → сигнал пина.
